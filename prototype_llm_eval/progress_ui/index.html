Progression status

Prototype progression verification

This page documents what the codebase actually implements. It does not simulate learner unlocks or a course map.

Verdict

Learner progression (sequential unlock, completion state, “next task” for a user) is not implemented in this prototype. There is no progression API and no persisted learner profile.

The only “progress” UI in the repo is on /eval-ui: it counts how many benchmark answer attempts have five human subtask labels saved in human_marks.csv. That supports research labelling, not learner gameplay.

What exists (evidence)

  • GET /api/demo/config — server mode, providers; includes use_fixed_dataset (benchmark bank for POST /generate-task when fixed mode is on), not learner progression.
  • POST /generate-task — returns a task (sampled from frozen bank or freshly generated). No unlock rules.
  • POST /api/demo/generate-live-task — one live task for demos; stored in task_store for marking only.
  • GET /api/eval/data + POST /api/eval/human-marks — frozen benchmark + human ground truth labelling.

What would be required for “full” progression

  • A learner identity (even a demo session id) and server-side state for completed tasks.
  • Rules mapping concept/difficulty → next task, or a curated graph of tasks.
  • APIs to read/update progression and UI that reads them (separate from eval human marking).
